## 交叉依赖（谁卡谁）

- 第 3 步不做 → 第 9 步的"老师打开固定版"必然停在 `eligibility_unavailable`（**fail-closed，不是故障**）。
- 第 4 步不做 → 实践第 7 步会在**学生花掉一次性票据之前**就拒（`session_store_unavailable`），不会出现"登录成功但会话记不住来源"。
- 第 5 步不做 → edu 侧提交与评阅无处落库。
- 第 6 步少给 `html_projects` 的 SELECT → 只是 `/state` 的 `title` 为 `null`，edu 两个列表要按明示回退显示"未命名作品"。
- 第 1 步的**隔离预览域**缺失 → P09 可以开，但**没有预览**：教师打不开固定版，清单 §7 第 6 小步必然失败。

## 容易误读的地方

- **「四个 origin」说的是四种角色，不是四个必须互不相同的域名。** 实践的 API 与页面可以同域——
  C05 甚至**要求**学生落地页与 `/api` 同源；**唯一必须不同源的是隔离预览域与应用**，学生 HTML 只在那里跑。
  edu 是对端，自然是另一个域。新增共享主机与具体域名须按具名环境确认；已有本机入口不等于公网测试域，本表不发明地址。
- **配置凭据（第 2、3 步）与启用后验证（第 7、8 步）是两回事。** 前者只能静态核：文件在不在、权限对不对、
  字段齐不齐、两侧是不是同一份；「日志里出现已装配」要等服务重启之后，属于第 7、8 步的验收项，
  **不能倒过来当作凭据步骤的完成条件**。
- 本表与清单都只是测试环境材料：**不授予** D-13 额度决定、真实学校开通或任何生产权利。
