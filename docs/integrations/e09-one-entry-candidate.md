## 二、先证明缺口，再改

裁定说的缺口是"C05 落地页清理凭据时把片段一起清掉"。真实浏览器一跑，**实际情况比裁定更细**，两点都记在这里：

1. **组件层确实丢**：只渲染落地页（不经过应用启动那一步）时，片段里的上下文在清理地址栏后就没有了。
   先写的两个用例在改动前失败，失败原文留在 `storage/private/e09-one-entry-pre-fix.txt`。
2. **整页打开时不是"丢"，而是"没人管"**：`main.jsx` 在任何页面渲染之前就会把片段里的上下文取走并清掉地址栏
   （凭据不该在地址栏多留一刻）。所以它其实还在内存里——但它**不管这次登录成没成、落在哪一页**，
   上一次登录留下的也可能被下一次接着用。第一次真实浏览器跑出来的就是这个事实，写在本包证据里。

3. **第三条是核收时读源码读出来的**（2026-09-24 定向修）：落地页原来把片段记在 `useRef(...).current` 上，
   等于"整个组件只认第一次到达"。同一条路由**不卸载**而换一张票再来一次（学生在同一个标签页里又从作业页
   点了一次），effect 会带着新票重跑，却仍拿着上一次的片段：要么把**上一次的作业按到新票上**，
   要么在首次片段已被启动清理时把**新票自己带来的那份弄丢**。两个定向反例在改动前都真的失败
   （`storage/private/e09-one-entry-ab-pre-fix.txt`），改成"按这一次到达取片段"后通过；
   同一张票在 StrictMode 下仍然只判定一次。

4. **最后一条只有真实浏览器才会暴露**：开发模式下 React StrictMode 会把落地页的 effect 跑两遍，
   而"判定这次到达能带哪个上下文"是**消耗性**的——第一遍取走，第二遍空手，于是刚点进来的作业凭空消失。
   前两次真实浏览器运行就是栽在这里（证据目录 `run-20260924T102103Z`、`run-20260924T103131Z` 保留）。
   修法与那张一次性票一样：**按票只判定一次**，两次挂载得到同一个答案。

所以本包做的不是"把丢掉的捡回来"，而是**给这次交接定规矩**：谁在什么条件下可以拿到它、什么时候必须丢掉。

## 四、边界（每一条都有用例）

- **落点只认服务端**：`entry` 必须是后端返回的 `ai-practice.html`；URL 上的 `entry`、`return_to` 或任何地址一律不看。
- **只认一个规范上下文**：`p09g.<base64url 载荷>.<base64url 签名>`，长度有上限；重复的 `p09_task`、畸形值、
  外部地址、其它片段参数一律当没有，也不转发。
- **只在内存、只在本标签页**：不写 localStorage / sessionStorage / cookie，不打日志，不进查询串，
  不进登录请求体，也不当登录身份——它证明的是"哪次作业"，不是"你是谁"。
- **片段属于这一次到达，不属于这个组件**：同一条路由换票再来一次时，读的是新票这一次的地址；
  判定仍按票去重，所以 StrictMode 的两遍 effect 对同一张票只判定、只消耗一次。
- **一次登录一次判定**：登录失败、落在非编辑器页面、或者同一个标签页里又来一次登录，上一次的立刻作废。
- **一票一次**：StrictMode / 重挂载下同一张 handoff 只兑一次，而且那一次成功导航不会把上下文弄丢。
- **没有上下文就是原来的样子**：面板照旧显示"没有作业上下文"，C05 行为一字未改。
- **不自动做事**：进来这一下不关联、不保存、不提交、不重试。

签名、学校、学生、作业、时效、一次性这些校验一条没降，全在后端原处；本包没有改后端、DDL 或依赖锁。

## 五、edu 那一半要发什么（最小格式）

一个按钮，一个地址：

```
https://<实践站>/auth/sso/consume?handoff=<一次性票>#p09_task=<任务上下文>
```

- `handoff`：edu 用原有 `/api/auth/sso/exchange` 换来的一次性票（43 字符），**只能用一次**；
  它的 `landing.entry` 必须是 `html`（或全称 `ai-practice.html`），否则学生不会落在编辑器。
- `p09_task`：edu 自己签的任务上下文，就是它今天放在编辑器链接上的那一个，一个字节都不用改
  （`purpose=website_artifact_link`，同一学生、同一作业、同一实例）。
- 放在 **`#` 片段里**，不要放进查询串：片段不会进任何服务器日志，也不会经 Referer 泄漏。
- 两者必须指向**同一个学生、同一次作业**；edu 在生成这个地址之前照旧做它自己的权限核验。
- 实践侧收到后：立刻把地址栏清干净 → 只有登录成功且落点是编辑器才留下 → 交给编辑器面板 →
  学生**自己点一次**"关联到教学任务"时，后端再对这份上下文验签、验归属、验时效。

edu 不需要新增任何接口或字段；这一包也没有给后端加线上字段。
