## 新 HTTPS 模块的实际边界

`backend/src/services/artifactHandoff/i03HttpsTransport.js` 是尚未装配的传输模块。构造参数必须完整显式匹配候选配置，无默认域名推导、Host 推导或响应 URL；配置不能切到星云或任意第三方。该匹配仅防配置混用，**不是生产数据集或教师资格证明**。未来冻结不同实例对时须另做受审配置，不能删掉检查。

仅接受调用方传入的一次动作、单个 JSON 对象和 UUID 幂等键；不创作协议版本/nonce、不换票、不判断身份、不自动重试。prepare 512KiB，其他控制请求 16KiB，响应 16KiB；固定超时、no-store 和未压缩 JSON 约束。返回有界未可信响应字节供未来正式解码器验证，HTTP 200 不产生 `succeeded` 或资源回执。正式解码器仍须处理 envelope、deadline、错误码/HTTP 配对、操作绑定和 open_target；调用方不能直接将原始响应展示或写日志。

本地 TLS 测试临时生成 CA 与证书，仅在测试中把固定主机的 socket 路由到 127.0.0.1 并信任临时 CA，保留真实 SNI/证书校验。验证有效证书成功、不可信链拒绝、可信 CA 但错误 hostname 拒绝且未发送 HTTP；测试记录实际 TLS 错误码，避免把其他连接错误误当证书验证成功。无生产网络写入。

复现：在 `backend/` 运行 `./node_modules/.bin/jest --runInBand --runTestsByPath src/__tests__/unit/services/artifactHandoffHttpsTransport.test.js src/__tests__/unit/services/artifactHandoffI03Client.test.js`。本轮 **35/35**：新传输 21，原客户端 12，加版本兼容拒绝 2。首次 TLS 测试路由未适配 Node 的 lookup `all` 返回格式，修正测试路由并验证真实 TLS 错误后全部通过；不把首次失败归因生产。

## 截止时间的源侧补充意见

当前 `i03Source.freeze()` 从本地选定时刻建立 `write_until=freeze+24h`、元数据 `expires_at=freeze+30d`；Identity 从首次 issue 建立窗口，两个起点可能不同。接受候选时不把本地时钟冒充 Identity 权威截止，也不把换票当延期。

拟消费规则：首次可信 issue 响应原样持久化操作截止；任何阶段返回不同值拒绝；源释放前同时满足快照仍在有效期与 Identity 截止。较早的本地正文清理只允许停止新写入，不能阻止已成功操作的 status/cancel 恢复。元数据与去重墓碑至少覆盖 Identity 的恢复窗口，不能在 freeze+30d 提前清掉晚 issue 的操作。首次 issue 响应丢失后，以同 binding 原操作恢复可信截止，再继续；不能回退到当前时间+24h。

请 I03 在冻结稿明确本地快照可以更早停止写入，以及 status/cancel 30 天的精确起点；建议统一为首次 issue，以 `operation_expires_at + 29d` 对齐源恢复元数据期限。正文期限与无正文恢复元数据分开，避免用恢复期限延长正文保存。此为技术消费意见，无需重问用户是否部署。V01–04 新候选端到端向量尚未运行；已有六组三端结果仍只证明 draft。

P03 正式 release 必须执行以下链，且拒绝分支不发送 commit：

1. 从可信当前会话得到本地账号；账号停用、过期、删除及会话失效即时拒绝，不从请求体取身份、不接受查询串 bearer 作为新入口身份。
2. 查当前正式教师资格和所需组属性的可信投影；有主源、版本/有效状态和撤销路径。源不可用、学生、普通非教师 user 一律拒绝，管理员无权代他人保存。现有 schema/标签不满足，此处待真实事实接入，不用开发名单顶替。
3. 从当前实例的会话/消息加载本人 completed 回答、精确选段和版本；继续复用 `source.js`/`prepareSelection` 的思考隔离和字节校验。明确校验每个附件可读且可持久复制，缺失或仅引用不通过；没有附件权利时也不能静默漏掉已选附件。
4. 锁住对应主体权限修订与源事实，重新检查 source/version/content、取消标志和操作截止，在同一可证明串行边界持久化 release。所有停用、换组、撤权、消息改动/删除、附件失效路径必须与该边界协调；仅加一把 P03 自用锁不能约束现有写路径。
5. 单独受限应用角色读必要权利/来源、写操作/快照/选择唯一键/取消意图/回执；迁移器另授 DDL。唯一键覆盖本地 owner、源/目标 instance、destination、selection hash。跨进程并发及重启恢复须在真实生产结构的隔离库验证，再经备份/迁移/双站受控发布。

现有 `MySQLDraftStore` 的事务、唯一选择及命名锁可作实现参考，测试事实行的 `active/eligible/copy` 与 `FOR UPDATE` 串行只证明实验场景；不可复制到生产当权利来源。跨进程撤权测试及受限角色/生产表仍未交付。本单没有为了清空待办部署合成身份或迁移生产库。
