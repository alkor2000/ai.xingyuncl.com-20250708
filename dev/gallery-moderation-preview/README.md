# Gallery moderation candidate

Local component fixture only. It does not connect to production, proxy an API, or supply a real login. `browser.cjs` intercepts API requests and rejects non-loopback browser requests. The PNG and one-second silent blue MP4 are synthetic. Start `server.mjs` with Node; it binds only 127.0.0.1:4417. Run the Playwright check once for images and once with `TEST_MEDIA=video`. The local Chromium executable, `/test` fixture mount and `/out` evidence mount are explicit in the test runner. On Windows, enter `wsl` first; these are WSL/ Linux processes.

The real-MySQL test `backend/src/__tests__/integration/galleryModeration.standalone.cjs` expects local development `DEV_MYSQL_ROOT_PASSWORD` in its environment. It creates a unique `gallery_review_test_<pid>_<timestamp>` database on 127.0.0.1:3307 and removes only that database afterwards. It never truncates a shared test database. Fixtures exercise both prior gallery boundaries and new moderation scenarios. `galleryReviewScan.test.mjs` uses Node's test runner; the media-decoding case needs local `TEST_FFMPEG` / `TEST_FFPROBE` executable paths.

## Behavior and release boundaries

- Scoped administrators can take down an approved item, leaving the author able to see the private asset and reason. Restore requires explicit review, a current revision, a successful generation, a valid private file and no account/hash block. Ordinary users cannot restore through publish.
- One report enters the same scoped reported queue. Three distinct users (default; server `GALLERY_REPORT_THRESHOLD`, integer 2–100) temporarily hide a work. Reporting never restricts an account. One report per user/work for the work's lifetime prevents repeated re-counting; restoration resolves reports without deleting their audit. An old reporter cannot repeatedly trigger hiding after restoration.
- Admin/super_admin authorization is unchanged: admin reviews its group’s student works; super_admin is global; no self-review. Reporter IDs are suppressed in the review history. Existing roles are not repurposed as new teacher permissions.
- Migration `20261110_001_gallery_reports_visibility.js` only adds reason/report columns and video reports. It is retry-safe and does not change visibility. Apply after the existing 11-05 / 11-06 safety migrations. Those older migrations have their own historic-withdrawal effects and must be accounted for by the release owner when deploying onto an older parent.
- Rollback application code retains additive columns, reports and audit. Do not run a destructive schema down or silently republish removed items. Restoring visibility is a reviewed business action, not an automatic deployment rollback.
- Controlled gallery links and protected media requests stop serving nonauthors after hiding. Already downloaded bytes cannot be revoked. Old public OSS URLs require the existing private-import/ACL workflow under a separate write approval; a readonly scan does not revoke them.
- This candidate does not enable automatic publication. It also does not yet connect the shared seven-category reviewer to the publish endpoint or implement the subsequently added batch-approval/class/time filters.
