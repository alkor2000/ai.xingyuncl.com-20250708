# 公开画廊老师审核

学生分享改为申请公开，只有老师对当前版本的具体图片作出通过决定后才写入 `is_public=1`。机器 `pass` 与人工公开许可是两项独立条件；机器复查或管理员内容处置会撤销公开许可。所有历史图片默认未获人工许可，迁移将当时仍公开的图片移入待审。

审核老师使用已有组管理员账号，只能查看和审核本组学生；超级管理员可审核全平台。两者都不能审核自己的作品。入口：系统设置 → 画廊·老师审核。老师检查完整图片和提示词，确认并填写理由后通过或驳回；列表只包含申请过公开的作品。色情裸露、粪便/食粪等恶心内容、辱骂及针对他人的羞辱均不允许公开。

待审期间学生可撤回。已通过后撤回再申请必须重新审核。服务端用行锁与修订号处理撤回、通过、下架的竞争；所有决定记录审核人、时间、理由、图片摘要。数据库 CHECK 阻止旧客户端直接把从未获老师许可的记录改为公开。API 还检查安全状态、真实文件和审核身份，不以 CHECK 代替业务鉴权。

百度配置缺失时，已有图片仍可由老师完整人工审核；明确被拦截的图片或相同摘要不得通过，须先由超级管理员复核。此前接入的生成/参考图安全审核仍在服务不可用时拒绝请求，不因老师审核功能而放开自动生成。图片文件保存在私有目录，预览需要鉴权；发布前还必须隔离旧 OSS URL。

发布沿用 `dev/RELEASE.md` 和工作区原生发布登记：先备份与演练加法迁移，再星云首站、北大 Docker。此说明及本地测试不代表部署成功。迁移不可自动回滚删除安全状态；退回旧应用时保留 CHECK，禁止重新开放未审核作品。

应急撤下、已不再带 `is_public=1` 的历史图片可从私有备份重新排入待审：目标后端环境运行 `scripts/gallery-review-backfill.js`，必须指定 `--manifest=<备份文件> --sha256=<已核实摘要>`，默认只读。`--apply --after=<上批游标> --limit=100` 分批执行。脚本只接受备份中曾公开的记录，核对作者/提示词/状态，跳过后来撤回、审核或已经入队的记录；绝不自动通过。需要预览时使用既有受限存储导入，或 `scripts/image-safety-sweep.js` 有界处理。备份含用户数据，不得提交 Git。

验证：独立 MySQL 测试覆盖迁移 CHECK、机器通过不自动公开、旧 SQL 写入拦截、组隔离、自审拒绝、私有预览、撤回竞争、过期修订、机器异常时的明确人工审核与审计。浏览器验证需检查老师队列、私有图片加载、检查确认、理由必填及通过后的刷新。合成图片仅验证交互和权限，不代替老师对真实作品的审核。

视频执行同一教师权限和提交/撤回/通过/驳回规则，入口为“视频画廊·老师审核”。老师须完整观看画面、声音和字幕，播放结束后才能勾选检查确认；浏览器播放结束事件只辅助操作，不宣称证明真人认真审查。视频无自动放行路径，参考帧复用图片审核并通过仅给供应商的短时私有 URL 传送。

新视频统一流式保存于 `storage/video-safety`，只接受 MP4，单个最大 250 MiB，不再先传公开 OSS；受限资源接口校验摘要，支持鉴权后的 Range 读取。播放器按需加载认证 Blob，避免列表一次下载所有视频。供应商原始地址、封面/GIF/尾帧和原始响应不会进入用户 DTO。缓存按安全修订号合并，旧任务快照不能恢复已屏蔽视频的播放地址。

历史视频使用 `gallery-review-backfill.js --media=video` 从本次撤下的私有备份排队，其他校验及分批参数与图片相同；审核页逐条导入旧视频到私有目录并撤销旧链接。非当前存储桶的历史资源不会自动搬运，需管理员从已核实的原桶恢复。Docker 维护脚本应使用 `docker exec -u nodejs`，PM2 应以应用进程同一系统用户执行，避免私有文件归 root 而后台无法读取。生产操作仍按既有原生发布和备份流程，不由本文授予发布权限。
